## What the project is

**AgileAgent — Multi-Agent AI Software Engineering Platform for Autonomous
Software Development.**

You describe a software idea in plain language. Eleven specialised AI agents
analyse requirements, decide which capabilities the project needs, design the
architecture and database, write frontend and backend code, review and improve
their own output, document everything, and return a downloadable ZIP.

**Critically it is NOT:** a trained model (no dataset, no training, no
accuracy/F1 — it orchestrates pre-trained LLMs via API), a chatbot (one input,
then eleven agents run autonomously), or RAG (uses typed shared memory, not
vector similarity — a deliberate decision because the state is small and
structured).

## The eleven agents

Manager · Business Analyst · Solution Architect · Database Engineer · Backend
Engineer · Frontend Engineer · QA Engineer · AI Review Engineer · Code
Improvement Engineer · Documentation Engineer · Artifact Manager.

The **Business Analyst** answers five capability questions (does data persist?
do different users see different data? is there an API? a backend? a UI?), and
those answers decide which agents run. A portfolio site gets 9 of 11; a hospital
system gets all 11. **Every skipped agent displays its reason.**

## Core design decisions — do not violate these

1. **Deterministic / AI boundary.** Build tooling (`package.json`, `tsconfig`,
   Dockerfiles, `pyproject.toml`) is emitted by hand-verified pinned code —
   **never** generated by a model. Same for ZIP creation, manifests, timelines,
   progress tracking, validation. A guarantee beats a probability.
2. **No agent calls a provider directly.** Every model call goes through
   `ProviderManager`. That single constraint is what makes failover automatic.
3. **Two-phase code generation.** Plan a file manifest, then generate contents
   in ordered batches. One completion for a whole app truncates.
4. **`depends_on` (ordering) vs `requires` (hard need)** are separate. Only a
   failed `requires` blocks an agent. A test enforces `requires ⊆ depends_on`.
5. **Extend, never rewrite.** Adding a provider or technology is a new file plus
   one registration line. Nothing above the LLM layer should ever change.
6. **SSE over `fetch`/`ReadableStream`**, not `EventSource` — EventSource can't
   set auth headers, and a token in the query string leaks into logs.

## LLM orchestration (the strongest part of the project)

Six providers: **Gemini · Groq · NVIDIA NIM · Ollama · OpenAI · Anthropic**.

Pipeline: `Cache → Route → Retry → Fail over → Record`

Priority is decided in four steps: (1) configured base order, (2) health filter
removing cooled-down providers, (3) task-kind reordering — code/review prefers
strong models, documentation/summary prefers cheap fast ones, (4) capacity
check moving providers that can't hold the prompt to the back.

Failure kinds: `RETRYABLE` (retry same provider) · `QUOTA` / `AUTH` /
`UNAVAILABLE` (fail over + cooldown) · `FATAL` (stop — all providers would
reject it identically).

## Positioning for reviews

**Related research:** MetaGPT (Hong 2023), ChatDev (Qian 2023) and AgileCoder
(Nguyen 2024) are the closest work — note AgileCoder's name similarity. The
multi-agent SDLC concept is **not novel**; do not claim invention. Our
differentiators are: capability-driven agent assignment, provider-resilient
orchestration, the deterministic build boundary, and decision traceability.
The orchestration side draws on a separate literature the SDLC papers ignore:
FrugalGPT, RouteLLM, GPTCache.

**"Why not just pay for ChatGPT?"** — "You're right that you can, but *you* would
be doing it. AgileAgent doesn't compete with ChatGPT; it **calls** it." Then:
truncation is a hard wall, you'd be the integrator, build files are guaranteed
not probable, a paid account is still a single point of failure, and a
conversation isn't a reproducible pipeline. Never claim better output quality —
it's the same models.

**Never say** ChatGPT "gets its resources from Google" (it's OpenAI, and LLMs
generate from training, not retrieval).
